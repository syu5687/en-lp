## 2. 【原因】

`contact/index.php` で電話番号は**任意**でした。

```html
<label>電話番号 <span class="req req--opt">任意</span>
  <input type="tel" name="tel" inputmode="tel">
</label>
```

v0275 でお問い合わせ種別をチェック項目にしたとき、任意3項目（お住まい・ご年代・性別）を削除しましたが、
**電話番号は「任意」のまま据え置いていました。**

担当者通知メールは**値がある項目だけを出す仕様**（`if (d[k])`）のため、
未入力だと「電話」の行そのものが消えます。空欄として表示されないので、
**入れ忘れたのか、もともと欄がないのかが通知からは分かりません。**

## 3. 【変更内容】

### 3-1. 電話番号を必須に

```html
<label>電話番号 <span class="req">必須</span>
  <input type="tel" name="tel" inputmode="tel" autocomplete="tel" placeholder="090-0000-0000" required>
  <span id="tel-note">お見積りやご相談の折り返しに使います。営業のご連絡はいたしません。</span>
</label>
```

### 3-2. 「営業のご連絡はいたしません」を電話欄の直下へ移動

電話番号を書きたくない方の抵抗は、**ほぼ「営業されたくない」**です。
これまでこの一文は送信ボタンの直前にあり、電話番号を入力する時点では目に入りませんでした。
**判断する場所に、判断材料を置きました。**

送信ボタン直前の一文は「送信後、受付確認の自動返信メールが届きます。」のみに変更しています。

### 3-3. 書式チェック（桁数だけ）

```js
let t = toHalf(String(v || '')).replace(/^\+81/, '0');
const n = t.replace(/[^0-9]/g, '');
if (n.length < 10 || n.length > 11) return '電話番号は10桁または11桁でご入力ください（例：090-0000-0000）。';
```

**厳しくしすぎると正しい番号を弾く**ため、桁数だけにとどめました。
全角数字・ハイフン・括弧・`+81` を受け付けます。

送信直前にも `window.__enRefreshTel()` で再チェックします（住所欄と同じ作り）。

## 4. ⚠ Worker 側は変更していません（重要）

サーバー側の必須チェックにも `tel` を足すのが筋ですが、**今回はあえて見送りました。**

`worker/en-contact/worker.js` の必須チェックはこうなっています。

```js
REQUIRED: ["name", "email", "message"],
```

ここに `tel` を足すと問題が起きます。**英語フォーム（`/en/`）には電話番号の欄がなく、
同じ Worker に送信しているためです。**

`/en/index.php` の送信項目を確認しました：
```
name / email / message / country / ashes_now / en_area / attend / timing / consent / website
```
→ **`tel` がありません。**

`REQUIRED` に `tel` を足すと、**海外からの問い合わせが全件 400 で弾かれます。**

`d.lang === 'en'` で出し分けることもできますが、
**判定を1つ間違えると問い合わせが全部届かなくなる**種類の変更です。
v0273〜v0274 で条件分岐を増やしたことが事故につながった経緯もあるため、今回はフロント側だけにしました。

ブラウザ側の検証は開発者ツールから回避できますが、**実在のお客様の入力漏れは防げます。**
ボット対策はハニーポットと表示からの経過時間で別途行っています。

**もしサーバー側にも入れる場合は、英語フォームに電話欄を追加してからにしてください。**

## 9. 自己検証

- **「連絡できない」は正確ではありませんでした。** メールアドレスは必須なので取れています。ただし墓じまいは現地確認と見積り説明が前提なので、**電話が取れないと実務が前に進まない**のは事実です。ご判断は妥当だと思います。
- **Worker を触らなかったのが今回いちばん大事な判断です。** `REQUIRED` に `tel` を足すのは自然に見えますが、英語フォームに電話欄がないことに気づかなければ、**海外からの問い合わせを全部落とすところでした。** 同じWorkerに複数のフォームがぶら下がっていることを、変更前に必ず確認してください。
- **離脱の増加は未測定です。** 一般に5〜10%と言われますが、このサイトでの実測値ではありません。KPIで見てから判断してください。
- **1週間で2件目の「連絡手段」のトラブル**です（11-04 住所／11-11 電話）。フォームを軽くする方向に寄せすぎていたのが原因だと考えています。**必須にすべき項目の判断は、CVRではなく「その情報がないと商談が進まないか」で決めるべきでした。**

## この方針が外れていた場合の代替ルート

2週間後に `contact_submit` が目に見えて落ちていた場合は、**必須を外すのではなく、逃げ道を1つ足します。**

```
電話番号 ＊
□ 電話が難しいので、メールで連絡してほしい   ← チェックで電話を任意に戻す
```

資料請求のチェックと同じ作りなので、実装も検証も既存の仕組みが使えます。
条件が1つ増えますが、**「必須のまま取りこぼす」より「逃げ道付きで取る」ほうが総量は増える**はずです。
判断は `contact_submit` の2週間の推移で行います。
