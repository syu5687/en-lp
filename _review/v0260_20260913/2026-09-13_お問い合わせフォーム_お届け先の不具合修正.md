## 【原因】2件とも同じ1か所が原因でした

`contact/index.php` にあった、この処理です。

```js
// 初めて開いたとき、上で選ばれた都道府県を住所の頭に入れておく（二度手間を減らす）
if (needsAddr && wasHidden && addrInp && !addrInp.value && prefSel && prefSel.value) {
  addrInp.value = prefSel.value;      // ← ここで「鹿児島県」が入る
}
```

**症状①**：`required` は「空でないこと」しか見ません。県名が入っているため検証を通過します。

**症状②**：郵便番号の自動入力は、上書き条件がこうなっていました。

```js
if (!addrInp.value.trim() || addrInp.value === zipAutoFilled) {   // 空 or 前回の自動入力値のときだけ
```

先に県名が入っているとどちらにも当たらず、**API は叩いているのに結果を捨てていました**。
通信エラーやCORSの問題ではありません。

親切のつもりの1行が、必須チェックを無効化し、自動入力も止めていた、という形です。

## 【変更内容】

### 1. 都道府県のプリフィルを削除

県名は郵便番号から自動で入るため、先に入れておく必要がありません。

### 2. 郵便番号→住所の自動入力を作り直し

- 上書き条件に「**都道府県名だけのとき**」を追加（手入力で県名だけ入れた場合も拾う）
- 全角数字・ハイフンを受け付ける（`８９０－００５３` でも動く）
- `input` に加えて `change` でも発火
- 連打対策：後から出した検索が古い結果に上書きされないようにした
- CORS が通らない環境に備えて **JSONP へ退避**（zipcloud の `callback` パラメータを使用）
- 状態を文字で出す：「住所を検索中…」／「続けて番地・建物名までご入力ください。」／
  「住所を自動で取得できませんでした。お手数ですが手入力をお願いします。」
- 自動入力後はカーソルを末尾に置いてフォーカス（そのまま番地を打てる）

### 3. 住所の入力チェックを追加（`setCustomValidity`）

以下を通しません。

| 入力 | メッセージ |
|---|---|
| `鹿児島県` | 市区町村・番地までご入力ください。 |
| `鹿児島県鹿児島市` | 市区町村・番地までご入力ください。 |
| `鹿児島県鹿児島市本港新町` | 番地までご入力ください（例：鹿児島市本港新町35）。 |
| `鹿児島県鹿児島市本港新町35` | 通過 |

判定は「都道府県名を除いた残りが4文字以上」かつ「数字・丁・番・地・号のいずれかを含む」。
漢数字（一〜十）も数字として扱います。

### 4. 郵便番号の桁数チェックを追加

7桁でなければ「郵便番号は7桁でご入力ください（例：890-0053）。」

### 5. 送信直前にも再チェック

`form.checkValidity()` の前に `window.__enRefreshAddr()` を呼び、
自動入力直後などで検証状態が古いまま送信されないようにしました。

### 6. バージョンを v20260713-0260 に更新

`includes/config.php` の `APP_VERSION` と `VERSION` ファイル。

  const z = String(d.zip || "").replace(/[^0-9]/g, "");
