# en1150｜GBPリンクでアンカーが効かない原因と修正

作成：2026-09-15
検証：本番 `/kaiyou-sou/` で実測（Chrome MCP・Windows）

---

## 1. 原因：`?` と `#` の順序が逆です

設定されたURL：

```
https://en1150.co.jp/kaiyou-sou/#goudou-schedule?utm_source=google&utm_medium=organic&utm_campaign=gbp_kagoshima
```

`#` 以降はすべて**フラグメント（アンカー名）**として扱われます。
つまりブラウザは、次の名前のidを探しにいきます。

```
goudou-schedule?utm_source=google&utm_medium=organic&utm_campaign=gbp_kagoshima
```

そんなidは存在しないため、**アンカーは効きません。**

さらに悪いことに、**UTMがクエリ文字列に入っていないため、GA4も読み取れません。**
アンカーと計測の両方が同時に壊れている状態です。

---

## 2. 正しいURL

**`?`（クエリ）が先、`#`（アンカー）が後**です。

```
https://en1150.co.jp/kaiyou-sou/?utm_source=google&utm_medium=organic&utm_campaign=gbp_kagoshima#goudou-schedule
```

### 実測で確認しました

この順序で本番にアクセスし、次を確認しています。

| 項目 | 結果 |
|---|---|
| `utm_source` | `google` ✅ |
| `utm_medium` | `organic` ✅ |
| `utm_campaign` | `gbp_kagoshima` ✅ |
| `location.hash` | `#goudou-schedule` ✅ |
| `id="goudou-schedule"` の要素 | **存在する**（ページ上部から10,319px地点） ✅ |
| スクロール | **到達を確認**（`documentElement.scrollTop = 10319`） ✅ |

## 4. 補足：アンカーは動きますが、体感は少し遅いです

`/kaiyou-sou/` の実測値です。

| 項目 | 値 |
|---|---|
| ページ全体の高さ | 17,027px |
| 日程セクションの位置 | 10,319px（**ページの約6割下**） |
| `scroll-behavior` | `smooth`（なめらかスクロール） |
| 遅延読み込み画像 | 35点 |
| サイズ未指定の画像 | 8点 |

`scroll-behavior: smooth` が効いているため、10,319pxの移動に**数秒かかります**。
訪問者には「一瞬ページ上部が見えてから、ゆっくり下へ動く」ように見えます。
壊れてはいませんが、速く着きたい人には回りくどく感じられる可能性があります。

### 選択肢

| 案 | 内容 | 向き |
|---|---|---|
| **A（推奨）** | アンカー付きのまま使う | 日程だけを知りたい人に親切。スクロール中に他の内容も目に入る |
| B | アンカーを外して `/kaiyou-sou/` へ | 冒頭から読ませたいとき |

**Aを推奨します。** GBP投稿で「10月24日」と書いて開いた人は日程を見に来ているので、
そこへ着地させる方が意図に合います。

### あわせて直しておくと良いこと（任意・優先度B）

サイズ未指定の画像が8点あります。`width` / `height` を入れると、
読み込み中にレイアウトがずれなくなり、**初回読み込み時のアンカー到達も安定します**。
今回の件とは別件ですが、表示速度（CLS）にも効きます。

---

## 5. 覚えておく一行

> **UTMは `?`、アンカーは `#`。必ず `?` が先。**

`...?utm_source=...&utm_campaign=...#anchor` の順序です。逆にすると両方効きません。
