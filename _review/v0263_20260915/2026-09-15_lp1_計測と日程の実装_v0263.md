## 1. ① CVが判定できない状態 → 解消

### やったこと

`lp1/script.js` の送信成功ブロックで、**`contact_submit` と `generate_lead` の両方**を送るようにしました。

```js
const lpEventParams = {
  form_name: 'lp1_kagoshima_ocean_burial',
  category: data.category || '(未選択)',
  method: 'inline_form'
};
/* 送信数の正指標。本体フォーム（/contact/）と同じ contact_submit を送る。 */
gtag('event', 'contact_submit', lpEventParams);
/* 既存イベント名は変更しないため generate_lead も従来どおり送る。 */
gtag('event', 'generate_lead', lpEventParams);
```

`generate_lead` を残したのは、**既存GA4イベント名を変更しない**という制約を守るためです。
これで `/lp1/` と `/contact/` を `contact_submit` という同一指標で並べられます。

送信前のボット判定（`elapsedMs >= 5000 && !data.website`）は従来どおりで、条件を満たさない送信ではGA4イベントを発火しません。

### まだ残っている作業（GA4管理画面）

1. カスタムディメンション `form_name`（イベントスコープ・パラメータ名 `form_name`）を登録

## 2. ② 日程がHTML直書き → 根治しました

### やったこと

`includes/goudou-schedule.php` と同じデータ源（`goudou_upcoming()`／管理画面 `/admin/goudou/`）を
`/lp1/` からも参照するようにしました。**カレンダー固定（10/25・12/20の手動更新）は不要になります。**

```php
$lp_next = null;
try {
  require_once dirname(__DIR__) . '/admin/includes/store.php';
  foreach (goudou_upcoming() as $g) {
    $sea = (string)($g['sea'] ?? '');
    if (mb_strpos($sea, '鹿児島') === false && mb_strpos($sea, '錦江湾') === false) continue;
    $lp_next = $g;
    break;
  }
} catch (Throwable $e) { $lp_next = null; }
```

- 「鹿児島」または「錦江湾」を含む海域だけを拾います（**福岡の日程がLPに出ることはありません**）
- 開催日を過ぎた日程は `goudou_upcoming()` が自動で外します
- 受付状況が「受付中」以外のとき（残りわずか／受付終了）だけ、日付の横に控えめに表示します
- 取得できないとき（データ無し・Firestore障害）は「次回開催日は現在調整中です」にフォールバック

### 動作確認（5パターン・すべてローカルで実測）

| 条件 | 出力 |
|---|---|
| 鹿児島・受付中 | `2026年 10月24日（土）` |
| 鹿児島・残りわずか | `2026年 12月19日（土）` ＋ 「残りわずか」 |
| 福岡の日程しかない | 「次回開催日は現在調整中です」 |
| データ無し | 同上 |
| Firestore障害（例外） | 同上（**LPは落ちません**） |

### 本番データの確認（実測）

本番 `/kaiyou-sou/#goudou-schedule` に登録されている内容を確認しました。

| 日付 | 海域 | 状況 |
|---|---|---|
| 2026年9月20日（日） | 福岡博多湾 | 受付中 |
| **2026年10月24日（土）** | **鹿児島・錦江湾** | **残りわずか** |
| 2026年11月15日（日） | 福岡博多湾 | 受付中 |
| **2026年12月19日（土）** | **鹿児島・錦江湾** | 受付中 |

フィルタ条件（鹿児島／錦江湾）に一致するため、**デプロイ後は 10月24日（土）＋「残りわずか」が表示されます。**
10/24を過ぎると自動で12月19日に切り替わります。

⚠ 従来のハードコード版には「残りわずか」の表示がありませんでした。実状に合わせた表示になります。

### 残るリスク（運用側）

管理画面に鹿児島の日程を登録し忘れると、LPは「調整中」になります。
既存の「月末30分ループ」のチェック項目に **「/admin/goudou/ に鹿児島の次回日程が入っているか」** を加えてください。

## 3. ③ 広告の出所が残らない → 解消

### 3-1. LP側（`lp1/script.js`）

LP到着時のURLから `gclid` / `utm_source` / `utm_medium` / `utm_campaign` / `utm_content` / `utm_term` を取得し、
`sessionStorage` に退避してから送信データに載せます。

- パラメータが取れなければ空文字。**送信は止めません**
- 各値200文字で切り詰め
- `sessionStorage` が使えない環境（プライベートモード等）でも try/catch で握り潰し、送信は継続
- あわせて `form_name`（`lp1_kagoshima_ocean_burial`）と `landing_page`（`/lp1/`）も送信

### 3-2. Worker（`worker/en-contact/worker.js`）

`logInquiry()` の転送項目に8項目を追加。さらに**担当者通知メール**に広告情報を追記します。

```
キャンペーン：<utm_campaign>
広告：<utm_content>
キーワード：<utm_term>
媒体：<utm_source> / <utm_medium>
Google広告クリック（gclid あり）
```

広告経由でないときは何も表示しません。**お客様向けの自動返信には出しません。**

### 3-3. サイト側API（`api/inquiry-log.php`）

保存ホワイトリストに `form_name` / `landing_page` / `gclid` / `utm_source` / `utm_medium` / `utm_campaign` / `utm_content` / `utm_term` を追加（長さ制限つき）。
HMAC署名検証は従来どおりです。

### 3-4. 管理画面（`admin/inquiries/index.php`）

- 一覧の「内容ほか」列に、広告経由のときだけ1行表示
  （例：`広告（クリック計測あり）：鹿児島_海洋散骨 / 広告A / 鹿児島 散骨 業者`）
- CSVエクスポートに8列を追加（フォーム名／着地ページ／広告媒体／広告メディア／広告キャンペーン／広告コンテンツ／検索キーワード／gclid）

これで **GA4とは独立した実データ**で「どのキャンペーンから何件の問い合わせが来たか」を確認できます。
