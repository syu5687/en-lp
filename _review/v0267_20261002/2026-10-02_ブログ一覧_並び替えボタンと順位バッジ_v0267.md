# /blog/ 並び替えボタン（人気の記事・いいねが多い記事）＋順位バッジ — v20260713-0267

作成：2026-10-02 ／ 対象：en1150（有限会社 縁）`/blog/` ／ 前段：v0266（いいね機能）

## 0. 先にお伝えすべきこと

**「アクセスが多い順」のデータが、自前計測には存在しませんでした。**

`assets/js/track.js` は `location.pathname` だけを送っており、`api/track.php` 経由で Firestore の
`pageviews` コレクションに記録されます。つまり**ブログ記事319本すべてが `/blog/` として1つに記録されており、記事ごとのPVは残っていません。**

```js
// assets/js/track.js（現状）
var data = JSON.stringify({ path: location.pathname, ref: document.referrer });
//                                 ↑ ?id=xxx が落ちる
```

一方 **GA4 には `page_location` がクエリ付きで入っているため、記事別PVは過去分も取得できます。**
そこでGA4から取る方式にしました。track.js の修正では今日以降のデータしか溜まらず、過去が使えません。

## 1. 設計 — 公開ページからGA4 APIは呼ばない

`admin/includes/ga4-report.php` の冒頭には「**管理画面（ログイン必須）専用。公開ページからは一切呼ばれないため、PVに比例した読み取り・API呼び出しは発生しない**」と明記されています。この前提を崩さない形にしました。

```
GA4 Data API ──(管理画面を開いた時／手動更新)──> Firestore  site_meta/blog_popular
                                                      │
                            公開ページ ──(en_cache 6時間)─┘  ※1ドキュメント読むだけ
```

| | 内容 |
|---|---|
| 公開ページ | Firestoreの**1ドキュメント**を読むだけ。外部APIを叩かないため、表示が遅くならず、GA4障害に引きずられない |
| 読み取り回数 | 1ドキュメント × 1日4回程度（6時間キャッシュ）。**PVに比例しない** |
| 更新のきっかけ | `/admin/likes/` を開いたとき、データが24時間以上古ければ自動更新。「今すぐ更新」ボタンも設置 |
| 保存形式 | `site_meta/blog_popular` に `map_json`（記事ID→PVのJSON文字列）・`updated_at`・`days`・`articles`。約10KBで1ドキュメント内に収まる |
| GA4 API 呼び出し | **1日1回程度**。管理画面側のみ |

公開ページでGA4を直接叩く案も検討しましたが、`ga4_batch()` のタイムアウトが25秒で、
キャッシュ切れの瞬間に訪問者を待たせる可能性があるため採用しませんでした。

## 2. 実装した内容

### 並び替えボタン（カテゴリ選択枠の下）

```
[新着順] [人気の記事] [いいねが多い記事]
```

- カテゴリのチップ（`.chip`）と同じ見た目を流用。**新しい部品を増やしていません**
- `?sort=popular` / `?sort=likes` で切り替え。既存の `?cat=` と**併用できます**（カテゴリ内でのランキング）
- 並び替え時は**上位30件**（`BLOG_SORT_LIST_COUNT`）を表示し、ページ送りはしません
- 実績が0の記事はランキングに載せません（0が並ぶのを防ぐため）
- ボタンの下に集計条件を1行で明示（「直近90日間のアクセス数が多い順に30件まで」）

**ご指示は2つのボタンでしたが、3つにしました。** 並び替えた状態から元に戻す手段がないと行き止まりになるため、「新着順」を先頭に置いています。カテゴリ側の「すべて」チップと同じ考え方です。

### 順位バッジ（1・2・3位）

- 全30件に順位の数字を表示し、**1〜3位だけ塗りつぶし**にしました
- 金銀銅・メダル記号・グラデーションは使っていません（AI感・テンプレ感の排除）。
  サイトの濃紺〜海ブルーの単色で濃淡をつけ、1位のみ円を少し大きく（34px / 2・3位は30px）
- スクリーンリーダー向けに「◯位」をテキストでも出しています（`.visually-hidden`）
- スマホ幅ではバッジを一段小さく（27px / 1位30px）

### 管理画面（`/admin/likes/`）を拡張

v0266 のいいね一覧に **PV列**を追加し、「いいねが多い順／アクセスが多い順」で切り替えられるようにしました。

- 統計：いいね合計／いいねがついた記事／**記事PV合計（90日）**／公開記事総数
- 「実績がある記事」「全記事」の切替
- 人気記事データの最終更新時刻と「今すぐ更新」ボタン
- CSVに**PV列を追加**
- ダッシュボードのカード名を「いいね・アクセス ランキング」に変更

## 4. SEO上の判断

**並び替えビュー（`?sort=`）は `noindex,follow` にしました。**

理由：中身は既存記事の並べ替えで本文が増えておらず、順位は変動します。インデックスさせると
`/blog/` と評価が分散し、クロールバジェットも消費します。`follow` なので記事へのリンクは辿られます。

canonical には `sort` を含めた自己参照URLを出しています（`?cat=` の既存挙動は変更していません）。

## 8. ダメ出し検証（リスクを 大きさ × 確率 で）

| リスク | 大きさ | 確率 | 対応 |
|---|---|---|---|
| **GA4のサービスアカウント権限が無く、人気の記事が出ない** | 中 | **中** — 未確認 | `/admin/ga4/` が見えているか先に確認。出ない場合はボタン自体が非表示になるだけで、ページは壊れない |
| 人気記事データの更新が止まる（管理画面を誰も開かない） | 中 | 中 | 14日を超えるとボタンが自動的に消える（古い順位を見せない）。**根治はCloud Schedulerで定期更新**（下記A） |
| いいねが0件のまま「いいねが多い記事」が空になる | 小 | **高** — 立ち上げ直後 | ボタンは出るが0件。気になる場合は `BLOG_SORT_ENABLED = false` で両方消せる |
| 人気順が古い記事に偏る | 小 | 高 | 90日集計のため、公開直後の記事は不利。意図どおり（累積の人気を見せる）だが、新着順ボタンを併置して補っている |
| 並び替えビューが検索結果に出て重複になる | 小 | 低 | `noindex,follow` で対応済み |
| 1〜3位のバッジが「ランキングサイトっぽく」見える | 小 | 中 | メダル記号・金銀銅・グラデーションを使わず単色の濃淡にした。それでも強いと感じる場合はCSS 3行で均一化できる |

### この実装が失敗するとしたら

- **失敗要因①**：GA4の `pagePathPlusQueryString` に期待したデータが入っていない。
  GA4は `pagePath`（クエリなし）と `pagePathPlusQueryString`（クエリ付き）が別の次元で、後者を使っています。**ここは実データでの確認が未了です。** 空になる場合は `pageLocation` に切り替えれば動きます（1行）。
- **失敗要因②**：そもそも押されない／見られない。並び替えボタンのクリックを計測していません。
  → **GA4で `sort` パラメータ付きのページビューを見れば、使われているか分かります。** 1か月見て使われていなければ `BLOG_SORT_ENABLED = false` にしてください。
- **失敗要因③**：自前計測（`pageviews`）とGA4で数字が合わず、堤様が混乱する。
  → 管理画面に「GA4から取得した直近90日間の記事別PV」と明記しました。`/admin/analytics/` の自前計測とは別物です。
