## 3. 【重要】`tel_click` / `line_click` の出所が判明

**`includes/ga4.php` の中に、全ページ共通の click デリゲートが入っていました。**

```
document.addEventListener('click', function (e) {
  ... href が tel: なら  gtag('event','tel_click',  {phone_number, page_path})
  ... host が line.me なら gtag('event','line_click', {page_path})
}, true);
```

### これで解けたこと

- **GA4管理画面の「イベントの作成」ではなく、サイト側のコードが送っていました。**
- したがって **二重計上の心配はありません。** 新LPに `tel_click` / `line_click` を足す必要もありません。
  `includes/ga4.php` を require していれば自動で計測されます（`/lp1/` は92行目で require 済み）。
- `generate_lead` は `/contact/` 側で送信、とコメントにも明記されています（9/7の調査結果と一致）。

### 訂正

9/7時点で私は「サイトコードに `tel_click` / `line_click` の発火箇所が見つからない。GA4管理画面の
『イベントの作成』の可能性があり、確定するまで実装しない」と報告しました。**これは私の調査漏れです。**
外部JS3本とインラインは見ましたが、`includes/ga4.php` を見ていませんでした。

### ga4.php の出力条件（把握しておくべき挙動）

- `en_nt` クッキーを持つ端末（管理画面に入ったことのある端末＝運営者）には**タグを出力しない**
- ホストが `en1150.co.jp` / `www.en1150.co.jp` 以外（ローカル・プレビュー・Cloud Run直URL）では**出力しない**

→ ステージングでの動作確認では計測が飛びません。設計として正しい挙動です。
