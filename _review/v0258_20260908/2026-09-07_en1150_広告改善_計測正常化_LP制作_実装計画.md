## 12. `generate_lead` の修正

| | 内容 |
|---|---|
| **【事実】** | `/contact/` の発火順序は「Workerへ POST → `res.ok` 確認 → 完了表示 → `form.reset()` → `looksHuman` 判定（経過時間5秒以上／ハニーポット `website` が空／メール正規表現）→ `gtag('event','generate_lead')`」。**送信成功時にしか発火しない正しい実装**。ボット対策はこの3点のみで、reCAPTCHA・Turnstile は未導入。ハニーポット `website` が画面に表示されている（幅26px×高さ45px、`display:block`／`visibility:visible`／`opacity:1`、`tabindex="-1"` のみ） |
| **【データ】** | `generate_lead` 261回／`form_start` 11回／`tel_click` 13回／`line_click` 10回 |
| **【仮説】** | 3点の弱い対策をボットが通過し、Workerが200を返し、フロントが成功扱いにしてCVを計上している。加えて可視のハニーポットに実ユーザーが誤入力すると、本物の問い合わせがスパム扱いになる |
| **【変更内容】** | ①ハニーポットを視覚的に完全非表示（`position:absolute; left:-9999px; width:1px; height:1px; opacity:0; pointer-events:none` ＋ `aria-hidden="true"`）②Cloudflare Turnstile を導入（**まず監視モードで1週間**）③Workerの応答に「受理したか」のフラグを持たせ、**受理時のみ** `generate_lead` を発火 ④`form_submit`（送信試行）と `form_error`（失敗）を追加 |
| **【期待効果】** | `generate_lead` が実問い合わせ件数と一致し、広告のCPA・LPのCVRが判断できるようになる |
| **【リスク】** | **CV数が見かけ上「激減」する。**修正日を基準日として記録し、修正前後を別データとして扱う運用を、実施前に合意しておく |
| **【確認KPI】** | `generate_lead` の件数がBrevoの実受信数と**一致するか**（一致＝成功） |
| **【前提】** | 8月の実問い合わせ件数（Q1）／Workerのスパム時の応答（Q2）／Turnstile導入可否（Q5） |
