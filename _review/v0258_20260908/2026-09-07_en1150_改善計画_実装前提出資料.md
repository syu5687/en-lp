## ■ 最初に：前回2資料の結論のうち、3点を訂正します

サイトの実装を実際に読んだ結果、分析資料の解釈が誤っていた箇所が3つありました。先に訂正します。

### 訂正1【重要】`generate_lead` は「/contact/ 表示で発火」していない

`/contact/` の実装を読んだところ、発火順序は次のとおりでした。

```
送信ボタン押下 → fetch(Cloudflare Worker, POST)
  → res.ok を確認（NGなら throw）
  → 完了メッセージ表示 → form.reset()
  → looksHuman 判定（経過時間 elapsedMs >= 5000 ／ ハニーポット website が空 ／ email 正規表現）
  → gtag('event','generate_lead')
```

**送信が成功したときにしか発火しない、正しい実装です。**「ページ表示で発火」という前回の推定は誤りでした。
`/contact/` 以外のページに `generate_lead` の記述は一切ありません（全17ページを走査して確認）。

では、なぜ8月に212件も記録されたのか。残る説明は次の2つです。

| 仮説 | 内容 | 検証方法 |
|---|---|---|
| **A（有力）** | スパムボットがフォームを送信し、Workerが200を返し、`looksHuman` も通過している | syu側：8月に問い合わせメールが何通届いたかを確認。212通前後なら確定 |
| B | Workerがスパムを破棄しつつ200を返す仕様で、フロントは成功扱いにして発火している | Cloudflare Worker のコードを確認 |

これを裏づける実装上の弱点を、サイト側で確認しました。

- **ボット対策は「ハニーポット＋5秒ルール＋メール正規表現」のみ。reCAPTCHA も Turnstile も入っていません。**
- そのハニーポット（`name="website"`）が **実際に画面に表示されています**（幅26px×高さ45px、`display:block` / `visibility:visible` / `opacity:1`）。`tabindex="-1"` は付いていますが視覚的には隠れていません。
  - ボットに見つかりやすい＝ハニーポットとして機能していない
  - 実ユーザーが誤入力すると **本物の問い合わせがスパム扱いになる**（＝機会損失）

前回「form_start（5件）より generate_lead（212件）が多いのはあり得ない」と書きましたが、`form_start` はGA4拡張計測のイベントで、このカスタムフォームでは正しく拾えていない可能性が高く、**分母として使えません**。この論拠も撤回します。

**結論：`generate_lead` の発火条件を変える必要はありません。直すべきはフォームのボット対策と、「Workerが実際に受け付けたか」をフロントが判定できるようにすることです。**

### 訂正2 `/kaiyou-sou/` のファーストビューに料金はある

実測したFV（上から700px以内）の内容：

```
H1: 鹿児島の海洋散骨（海洋葬）
P : 「海に包まれて眠りたい」——大切な方の想いを、母なる海へ
P : 委託海洋葬 54,450円〜（期間限定・通常66,000円） 合同…
```

料金はFVに入っています。表示速度も TTFB 322ms / load 1.96秒 と良好。
「FVに料金・流れ・エリアが足りない」という前回の指摘は**当たっていません**。原因は別（後述）。

### 訂正3 `/grave/` に対応エリアの記載はある

`h1` が「**鹿児島の**墓じまい、撤去から納骨まで一括対応」、本文に「鹿児島」24回、`h2` に「対応エリア」セクションあり、`/area/`（対応エリアページ）も別途存在。
「対応エリアを明示する」という前回の提案は**すでに実装済み**で、再提案の必要はありません。

## 2. 問題点一覧（一次確認に基づく）

### P-1【最重要／計測】フォームのボット対策が弱く、CV数が信用できない
- 対策はハニーポット＋5秒＋メール正規表現のみ。reCAPTCHA / Turnstile なし
- **ハニーポット `website` が画面に見えている**（26×45px）。ボット対策として機能せず、実ユーザーの誤入力でCVを取りこぼす二重の問題
- 8月 `generate_lead` 212件／127ユーザー。8/26は日本国内53セッションに対しCV43件、8/31は131セッションに対し46件。実在の問い合わせ数としては成立しない
- **フロントは「Workerが200を返した」だけで成功扱いにしている**。Workerがスパムを破棄していても発火する

### P-2【計測】GTMが入っていない
- サイトは `gtag.js` 直書き。GTMコンテナは0
- 結果として、計測の追加・修正は**すべてサイトコード側の作業**になる（管理画面だけでは変えられない）
- 逆に言えば、Claude側で実装できる範囲が広い

### P-3【計測】`tel_click` / `line_click` のコードがサイト内に存在しない
- 全ページを走査したが、`tel_click`・`line_click` を送出するコードは1行も無い
- それでもGA4には `tel_click` 6件・`line_click` 2件が記録されている
- → **GA4管理画面の「イベントの作成」機能でクリックから生成している可能性が高い（未確認）**。syu側で確認が必要
- 各ページに `tel:` リンクは1〜5本、LINEリンクは0〜3本あり、素材は揃っている

### P-4【計測】内部・テストトラフィックが本番データに混入
- `tagassistant.google.com` 10セッション・CV4件／`claude_test` 7セッション／Cloud Run検証環境 4セッション
- 8月のCV212件のうち、少なくとも4件はTag Assistant由来

### P-5【計測】海外データセンター由来のアクセスが全体の44.6%
- シンガポール1,255セッション（エンゲージ率0.16%）。7月も985セッション
- GA4の素の数字が実態から乖離し、月次レポートが読めない

### P-6【広告】流入の73%が「地域指定なし」キーワードに使われている
- 地域なし218セッション（エンゲージ率48.6%）／鹿児島37（62.2%）／福岡圏38（60.5%）／商圏外5（20.0%）
- **地域名付きの方が12ポイント高いのに、予算の大半が地域なしに流れている**

### P-7【広告】「墓じまい」の全国配信が最大の無駄
- 墓じまい×地域なし58セッション：エンゲージ率32.8%／平均滞在54秒／PV1.12
- 墓じまい×鹿児島8セッション：エンゲージ率62.5%／平均滞在206秒／PV2.12
- とくに「墓じまい費用」単体19セッションは 21.1%／21.5秒／PV1.05
- **原因はページではなく、施工エリアが鹿児島・福岡に限られるサービスを全国に出していること。**`/grave/` は h1 に「鹿児島の」と書いてあるため、全国の検索者はFVで離脱する（正しい挙動）

### P-8【広告／SEO】「和布刈神社散骨」は競合の指名検索である
- Google検索で一次確認：**和布刈神社（mekarijinja.com）が自社で海洋散骨を提供**（委託70,000円・生前申込65,000円・神職が執行・毎月1度定期便）
- つまり「和布刈神社 散骨」＝**神社のサービスを探している検索**。縁を探している検索ではない
- 実データも一致：8セッション・エンゲージ率50%・平均滞在57秒・CV0（福岡圏で最も滞在が短い）
- 同エリアの競合：ブルーオーシャンセレモニー（下関・唐戸発）、燈台舎（小倉沖）、sea-ceremony.com（北九州）、sankotsu-likefamily.com（「和布刈神社沖」を散骨海域として掲載）
- **「和布刈神社で散骨できます」という表現は事実に反するうえ、他社サービスの横取りになります。絶対に使用しません。**

### P-9【SEO】「海洋散骨 福岡」で圏外
- Google検索（2026-09-07・日本）で上位16件に en1150 は**不在**
- 上位は haka-mori.co.jp / kaiyoso.com / ocean-memorial.com（永興寺）/ sumiyoshi-jinja.jp（姪浜住吉神社）/ yamanostone.co.jp（山野石材）/ morinoan.co.jp（森の庵）など、寺社・石材店・専業が並ぶ激戦区
- `/kaiyou-sou/fukuoka/` はインデックス済み（`site:` 検索で1位表示）だが順位が付いていない
- **福岡の海洋散骨は当面「広告でしか取れない」。SEOは中長期の投資と割り切る必要がある**

### P-10【CRO】`/kaiyou-sou/fukuoka/` の直帰率が高い理由は「情報不足」ではない
- 情報量はむしろ**過多**：8,600語・h2が19本（六価クロム／法律／業者選び6ポイント／県外の方へ／FAQ／レポート／実施予定日）
- 電話リンク5本・LINEリンク3本と、CTAは `/fukuoka/`（電話3・LINE0）より多い
- 平均滞在は `/fukuoka/` とほぼ同じ（159.5秒 vs 154.0秒）
- **差が出ているのは「開いた直後に帰る人の割合」**（直帰率54.7% vs 30.3%）
- 有力な原因は**地理の不一致**：このページは「博多湾」16回に対し「関門」0回・「北九州」1回。福岡圏の広告検索語句の43%は和布刈・関門海峡・下関・北九州＝**関門エリア**。北九州・下関の検索者が「博多湾」の見出しを見て即離脱している

### P-11【CRO】`/fukuoka/` が高く見えるのは回遊ハブだから
- `/fukuoka/` は「福岡向けの詳しいご案内」で他ページへ送る構造。PV/セッション1.61、直帰率30.3%
- エンゲージセッションの定義（10秒超 **または** 2PV以上 **または** キーイベント）上、**2ページ目に進みやすいページは自動的にエンゲージ率が上がる**
- したがって「福岡広告の遷移先を `/fukuoka/` に寄せる」という前回の提案は、**指標の性質差を実力差と読み違えている可能性があり、根拠として弱い**。A/Bテストで判断すべき事項

### P-12【SEO】`/powder/` の正規URLがねじれている
- `/powder/` の canonical が `/powder-cleaning/` を指している
- しかし実績は逆：自然検索は `/powder/` に30セッション・エンゲージ率90.0%・PV3.8（全ページ中最高）、`/powder-cleaning/` は5セッション
- 広告は `/powder-cleaning/` に19セッション送っている
- **評価が集まっているURLと、正規と宣言しているURLが食い違っている**。ただし現状うまく動いているため、慎重な検証が必要

### P-13【技術】`/kaiyou-sou/fukuoka/` で `:8080` への旧リダイレクトが残存している可能性
- 実機Chromeで `https://en1150.co.jp/kaiyou-sou/fukuoka/` を開くと `http://en1150.co.jp:8080/fukuoka/` に転送され、**Cloudflare 522（約39秒待ち）** になる現象を2回再現
- 同URLに `?nocache=…` を付けると正常表示（TTFB 327ms）。`fetch`／WebFetch／`site:`インデックスはいずれも正常
- → **過去に存在した301リダイレクトがブラウザにキャッシュされたもの**と推定（未確認）。現在のサーバー応答は200
- 影響範囲：当時アクセスした実ユーザーのブラウザにも同じキャッシュが残っている可能性がある。広告は `gclid` 付きURLのため回避できている一方、**自然検索のクリーンURLは影響を受ける**
- syu側で、当時 `:8080` へのリダイレクト設定（Cloudflare Rules／WordPress／リバースプロキシ）が存在したかの確認が必要

### P-14【CRO】スマホの固定CTAが無い
- 主要ページの固定要素は `site-header` と `fontsize-ctl` のみ。**電話・LINE・問い合わせの固定CTAは未設置**
- 日本国内スマホ877セッション（エンゲージ率59.1%）に対し `tel_click` 6件・`line_click` 2件

### P-15【CRO】診断機能が使われていない
- `shindan_nudge_show` 32回 → `shindan_start` 3回（すべて同一1ユーザー）
- `/shindan/` への自然検索着地は7セッション（エンゲージ率71.4%・平均滞在675秒）と、**着いた人の反応は極めて良い**
- 表示はされているが開始されない＝訴求文・設置位置の問題

### P-16【GEO/LLMO】素地はあるが、AI向けの「答えの単位」が弱い
- JSON-LDは各ページ2〜9ブロックと整備済み。`/area/`・`/flow/`・FAQも存在
- 一方、AI検索が引用しやすい「一問一答の粒度」「料金の構造化」「対応可否の明示」はページ内に散在している
- AI経由8セッション（エンゲージ率71.4%）と質は高いが、母数が小さい

【第3段階】LP改善（2〜3週間）
  着手条件：第1段階完了（CVが測れる状態）
  作業：C-8（/kaiyou-sou/ 地域導線）→ C-9（/service/）→ C-7（スマホCTA）→ C-11（診断導線）

  完了条件：各変更の前後4週間でエンゲージ率・直帰率・CVを比較できる状態

【第4段階】SEOコンテンツ強化（1〜3ヶ月）
  着手条件：M-15（Search Console接続）完了、M-13・M-14（対応市区町村・補助金の一次確認）
