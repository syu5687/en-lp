## 2. 【原因】IDセレクタの `display` が `hidden` 属性に勝っていた

`contact/index.php` の `<style>` 内、この1行です。

```css
#post-addr{border:1px solid #eadfc4;border-radius:10px;padding:14px 16px;background:#fffdf9;display:flex;flex-direction:column;gap:10px}
```

`hidden` 属性は、ブラウザ標準（UAスタイルシート）の `[hidden]{display:none}` で効いています。
**作者が書いたCSSは、UAスタイルシートより常に優先されます。**
`#post-addr` に `display:flex` を書いた時点で、`hidden` は無効になります。

`#delivery-box`（146行目）と `#goudou-date-field` には `display` を書いていないため、正しく閉じていました。
**`#post-addr` だけが該当**します。他に同じ状態の要素はありません（本番で全 `[hidden]` 要素を走査して確認）。

### これは v0273 で入った不具合ではありません

このCSS行は v0259〜v0260（2026年9月）から変わっていません。
v0273 の変更はJavaScriptのみ（5か所の明示置換・assert付き）で、CSSには触れていません。
**9月から今日まで、お届け先欄はずっと表示されたままだった**ことになります。

### なぜ2回のテストで見逃したか

9月13日（14項目・17項目）と11月4日（15項目）のどちらも、
`contact/index.php` から**フォームとスクリプトだけを取り出した検証ページ**で試験していました。
**ページ自身の `<style>` を読み込んでいなかった**ため、`hidden` 属性は期待どおり効き、
「住所欄が消える OK」と判定されていました。

`el.hidden === true` を見るだけでは足りず、**実際に画面に出ていないか**（`getBoundingClientRect().height === 0`）
を見る必要がありました。今回からそちらで判定します。

## 3. 【影響】入力されたお届け先が送信直前に捨てられていた

ここが実害です。送信処理にこの2行がありました。

```js
if (document.getElementById('post-addr').hidden) { delete data.zip; delete data.addr; }
```

`hidden` 属性は立ったままなので、**画面に出ている欄にお客様が住所を入力しても、
送信直前に `data.zip` と `data.addr` が削除されていました。**

つまり 9月以降、「資料請求」や「ガイドブック＋郵送」を選ばずに
**見えている住所欄へ自分から記入した方の住所は、こちらに届いていません。**

11月4日の小田ルリ子様のケースも、**住所を入力されていた可能性があります（未確認）。**
送信データが残っていないため、入力されたのか空のまま送られたのかは判別できません。
お電話で伺う際、「先ほどご住所はご入力いただきましたか」と一言確認いただくと、
この影響の有無がはっきりします。

## 4. 【変更内容】

### (1) `hidden` を確実に効かせる

```css
#post-addr{…;display:flex;flex-direction:column;gap:10px}
/* v0274：ID指定の display:flex が hidden 属性（UAの display:none）に勝ってしまい、
   お届け先が常に表示されたままになっていた。属性セレクタを足して確実に閉じる。
   同じ理由で #delivery-box と #goudou-date-field にも display を書かないこと。 */
#post-addr[hidden]{display:none}
```

### (2) 「必須」バッジを実際の状態に合わせる

郵便番号・ご住所のバッジは**HTMLに「必須」と直接書かれていた**ため、
v0273 で任意表示にしたときも赤い「必須」のままでした。これが
「最初から必須で表示されている」という見え方の半分です。

```js
const setReqBadge = (el, required) => {
  el.textContent = required ? '必須' : '任意';
  el.classList.toggle('req--opt', !required);
};
```

任意のときは灰色の「任意」バッジになります。

### (3) 送信データの判定を `hidden` から「値が入っているか」へ

```js
// 変更前
if (document.getElementById('post-addr').hidden) { delete data.zip; delete data.addr; }
// 変更後
if (!String(data.zip  || '').trim()) delete data.zip;
if (!String(data.addr || '').trim()) delete data.addr;
```

欄を閉じるときに値は空にしているので、結果は同じです。
**ただし、今後CSSやレイアウトが原因で欄が出てしまっても、
入力されたお届け先が黙って捨てられることはなくなります。**

### (4) 検証ページにページ自身のCSSを読み込む

今回から検証ページに `<style>` を含め、`hidden` 属性ではなく
**実際の描画高さ**で判定します。同じ見逃し方はできなくなります。

## この方針が外れていた場合の代替ルート

`#post-addr[hidden]{display:none}` で閉じない環境（古いブラウザでCSSの属性セレクタが効かない等）が見つかった場合は、
**CSSに頼らず JavaScript から `style.display` を直接操作する**形に変えます。
`el.hidden = true` と同時に `el.style.display = 'none'` を書けば、CSSの指定に関係なく確実に閉じます。
やや強引ですが、表示の正しさを最優先するならこちらです。
