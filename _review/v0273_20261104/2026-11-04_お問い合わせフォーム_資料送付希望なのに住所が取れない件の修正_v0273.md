## 2. 【原因】牧瀬さんの見立てどおりです

`contact/index.php` のお届け先（郵便番号・ご住所）の表示条件は、v0260 以降こうなっています。

```js
const needsAddr = isShiryou || (wantsGuide && !!(dlvPost && dlvPost.checked));
```

つまり住所欄が出るのは、次のどちらかのときだけです。

1. **お問い合わせ種別で「資料請求（無料）」を選んだ**
2. **無料ガイドブックにチェックを入れ、お届け方法で「詳しい資料を郵送で受け取る」を選んだ**

小田様は**どちらもされていません**。種別は未選択、ガイドブックも未チェックで、
**内容欄に「パンフレットを、送付希望です。」と文章で書かれました。**

結果、住所欄は一度も画面に出ず、都道府県だけが残りました。

### これはバグではなく、想定の抜けです

コードは設計どおりに動いています。設計のほうが「資料がほしい人は必ずチェックボックスを押す」
と決めつけていました。実際のお客様は**文章で書きます**。特に高齢の方ほどその傾向が強く、
今回の方は「送付希望です」という、これ以上ないほど明確な言葉で書かれていました。

受け取る側の仕組みがそれを読めていなかった、というのが正確な原因です。

## 3. 【変更内容】2段構えで受け止める

### 3-1. フロント側（`contact/index.php` v0273）

**(1) 内容欄の文章から郵送希望を読み取って、住所欄を「任意」で開く**

```js
const POST_WANT = /(郵送|送付|パンフ|カタログ|冊子|資料|送ってくだ|送って下さ|お送りくだ|お送り下さ|届けてくだ|届けて下さ|郵便で)/;
const POST_DENY = /(不要|いりません|要りません|結構です|送らないで|必要ありません)/;
```

- 内容欄に入力があるたびに判定し、当たれば住所欄を開きます
- **required にはしません。** 誤検知で「送信できない」状態を作るほうが損失が大きいためです
- 見出しは「資料の郵送をご希望の場合は、お届け先をご入力ください（**任意**）」
- いちど開いたら閉じません（書き直しで欄が消えるのを防ぐ）
- 「資料は不要です」のような否定文では開きません

**(2) 送信直前の最後の砦（1回だけ止める）**

郵送希望らしい文章なのに住所が空のまま送信ボタンが押されたとき、1回だけ止めてご案内します。

> 資料の郵送をご希望でしょうか。ご希望でしたら、お届け先（郵便番号・ご住所）をご入力ください。
> ご不要の場合は、もう一度「送信する」を押していただければそのまま送信されます。

同時に住所欄までスクロールし、郵便番号欄にフォーカスを当てます。
**2回目の送信は止めません。** 誤検知で問い合わせ自体が送れなくなる事故を避けるためです。

**(3) 必須と表示を分離**

```js
// 変更前：setField(el, show) … 表示＝必須、非表示＝値を消す
// 変更後：setField(el, required, visible)
const addrRequired = isShiryou || (wantsGuide && !!(dlvPost && dlvPost.checked));  // 従来どおり
const needsAddr    = addrRequired || msgPostHint;                                   // 任意表示を追加
```

値を消すのは**欄を閉じるときだけ**にしました。任意表示のまま消えると入力が飛ぶためです。

### 3-2. サーバ側（`worker/en-contact/worker.js` v0014）

JavaScriptが動かない環境や、お客様が入力されなかった場合の最後の砦です。

**担当者通知メールの先頭に警告を出します。**

> ⚠ **資料の郵送をご希望の可能性があります。お届け先の記載がありません。**
> お電話（080-8360-3626）またはメール（…）でお届け先をご確認ください。

- 電話番号・メールアドレスはタップできるリンクにしています（その場で発信できます）
- **件名にも `【要・住所確認】`** を付けます。受信箱の一覧で気づけます
- 日本語に加え、英語フォーム向けの語（brochure / pamphlet / by post 等）も判定に入れました

判定条件：

```js
(日本語または英語の郵送希望ワードを含む) かつ (否定語を含まない) かつ (住所が6文字未満)
```

## 9. 自己検証

- **見立ては牧瀬さんの指摘どおりでした。** 「資料請求にチェックが入っていないと住所が表示されない」が原因です。正確には「種別＝資料請求」または「ガイドブック＋冊子郵送」のどちらかが必要でした。
- **根本的には、2026-09-13 に直した方向の延長線上の問題です。** あのときも「住所欄の表示条件がチェック操作に紐づいている」ことが事故の元で、条件を整理しました。今回は「そもそもチェック操作をしない人」が抜けていた、という一段外側の抜けです。
- **「資料」という語を判定に入れるか迷いました。** 「資料を見ました」のような文でも開いてしまいます。ただ今回の方は「パンフレット」「送付」の両方を書いているので、「資料」を外しても拾えました。それでも入れたのは、「資料ください」だけ書く方のほうが多いと見ているためです。誤検知のコストが「欄が1つ余分に出る」だけなので、拾う側に倒しました。
- **一番効くのはWorker側の警告だと思っています。** フロント側はお客様の協力が要りますが、Worker側は確実に担当者の目に入ります。
- **検証はPlaywrightの実機操作で行いました。** コードを読んだだけの「直したはず」にはしていません。

## この方針が外れていた場合の代替ルート

ワード判定の誤検知が思ったより多い、または「文章で書く人」がそもそも少なかった場合は、
**判定をやめて、お届け先の欄を常時「任意」で表示する**ほうが素直です。
「資料の郵送をご希望の方は、お届け先をご入力ください（任意）」という欄を最初から出しておけば、
ワード判定は不要になります。入力項目が1つ増えることによる離脱が心配ですが、
任意かつ折りたたみ表示にすれば影響は小さく抑えられます。
判定の誤検知が目立つようなら、こちらに切り替えます。
