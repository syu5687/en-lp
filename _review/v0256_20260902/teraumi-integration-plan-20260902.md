## 0. 先に結論

teraumi.com は独立サイトではなく、**有限会社 縁が2023年12月から運営してきた自社サービスの専用サイト**でした。会社概要も代表者も問い合わせ先メール（info@en1150.co.jp）も en1150 と同一です。ルートページから en1150.co.jp への発リンクが11本あり、実質的にはすでに「縁のサイトの一部」として動いています。

したがってこの統合は「他社サイトの吸収」ではなく、**分かれてしまっていた自社の情報を1つに戻す作業**です。この前提が、以下すべての設計判断の土台になっています。

そのうえで、今回いちばん注意が必要なのは**旧サイトのコピーをそのまま持ち込めない**点です。旧サイトの中心的な訴求は「散骨すると手を合わせる場所がなくなるから、寺院にも納骨する」という論法で組み立てられており、これは今回の仕様§3で明確に禁止されています。また旧サイトの全ページtitleに入っている「新しい供養のカタチ」は、en1150 の禁止語リストに載っています。**移植するのは事実（料金・寺院・流れ・実例・写真）であり、文章はほぼ全面的に書き直します。**

## 2. 設計の骨格（なぜこの形にしたか）

### 2-1. teraumi は「10番目のサービス」として `SERVICES` 定数に入れる

`includes/config.php` の `SERVICES` 定数は、**1か所直すだけで6か所に反映**されます。

```
SERVICES に1行追加
 ├→ includes/header.php   グローバルナビ「サービス一覧」ドロップダウン
 ├→ includes/footer.php   フッターのサービス一覧
 ├→ contact/index.php     お問い合わせ種別のセレクト（＝仕様§16の要件）
 ├→ kuyou/index.php       ご供養についてのサービス一覧
 ├→ sitemap.php           sitemap.xml へ自動掲載
 └→ includes/jsonld.php   Organization の OfferCatalog
```

個別に6ファイル触るより差分が小さく、抜け漏れも起きません。**これが「サービスを増やした」ではなく「体系の中に吸収された」状態をコードレベルで担保する方法**です。

ただし**トップページ（`index.php`）だけは別扱い**にします。トップは独自のサービスカード群を持っており、ここに10枚目を横並びで足すと仕様§14が禁じる「主力サービスとして大きく追加」になります。トップには後述の「一つに決めなくても大丈夫です」導線だけを入れます。

### 2-2. 表記を1つに固定する

全ページで以下に統一します。

> **寺院納骨＋海洋散骨「teraumi（てらうみ）」**

- 単独の「teraumi」だけの見出し・カードは作らない
- 旧ロゴ・旧ブランドカラーは使わない
- ただし**「寺院納骨」だけでは不正確**です。実際の納骨先には神社（神徳稲荷神社）と霊園（谷山御所霊園・新生田上霊園）が含まれます。本文では「提携する寺院・神社・霊園」と正確に書き、サービス名としての表記のみ「寺院納骨＋海洋散骨」で統一します

### 2-3. 「迷わせない」ための3つの仕掛け

仕様§6の「選択肢を増やさない」を、具体的に次の3つで実装します。

**① teraumi を独立した第4の選択肢として並べない。**
既存の `#bunkotsu`「すべてを海に還さなくても、かまいません」の中に、**3つ目の残し方**として入れます。今そこには「手元供養」「メモリアルジュエリー」の2枚があるので、「寺院・神社に納める」を3枚目として並べます。ユーザーから見ると新サービスの追加ではなく、**すでに読んでいた話の続き**になります。

**② 診断では質問を1問しか増やさない。**
既存の `i3` / `k1` / `m2` で「一部は手元に残したい」を選んだ人にだけ、「どこに残したいですか」を1問足します。「すべて還したい」を選んだ人には**teraumiは一切出しません**。仕様§4の「teraumiが不要な方」を、表示ロジックで守ります。

**③ 通常の海洋散骨を否定する文を1文も書かない。**
`/teraumi/` の「通常の海洋散骨との違い」セクションは、**比較表ではなく「向いている人／向いていない人」の並列表**にします。teraumiの列だけを強調せず、通常の海洋散骨の列に「海そのものが、手を合わせる場所になります」と明記します。

### 2-4. teraumi をボトルネックにしないための設計

270,000円は、委託海洋葬54,450円の**約5倍**です。ここが最大のリスクです。

- **料金を最初に見せない。** `/teraumi/` のFVには金額を置かず、「一部を寺院に納めたい」という迷いから入ります（仕様§8）。金額はページ中盤の「料金」セクションに、**内訳とセットで**出します
- **「270,000円が高い」と感じた人の逃げ道を必ず用意する。** 料金セクションの直後に「海洋散骨＋手元供養なら 54,450円＋分骨5,500円〜」という比較を置き、`/temoto-kuyou/` へリンクします。teraumiを売り込まず、**予算に合う方を選べる**状態にします
- **主CTAは申込ではなく相談。** 仕様§15どおり「どの供養方法が合うか相談する」を主CTAにします
- **GA4で「teraumiを見た人の問い合わせ率」を単独で追える**ようにします（§14）。下がったら露出を減らせる設計にします

## 23. 設計の説明（仕様§31の後半への回答）

### なぜこの設計にしたのか

teraumi.com は**すでに縁のサイト**でした。会社概要も代表者も問い合わせ先メールも同一で、ルートページから en1150.co.jp へ11本リンクしています。つまり今回やるべきことは「他社を吸収する」ことではなく、**2つに分かれていた自社の情報を1つに戻す**ことです。

だから新規ページは `/teraumi/` **1本だけ**にしました。旧サイトの9ページ分は、この1ページと既存ページに畳み込みます。ページを増やせば増やすほど「サービスが増えた会社」に見え、内部リンクも薄まります。仕様§14の「サービスが増えた、ではなく、希望に合わせて組み合わせられる」を実現する最短の形が、**ページを増やさないこと**でした。

`SERVICES` 定数への1行追加という実装を選んだのも同じ理由です。ナビ・フッター・フォーム・sitemap・構造化データの5か所に同時に反映されるため、teraumiだけが特別扱いされる余地がコード上に生まれません。**「体系の中の1つ」であることを、実装の構造そのもので担保しています。**

### ユーザーを迷わせないために何をしたか

3つです。

**1つ目は、teraumiを新しい選択肢として並べなかったこと。** `/kaiyou-sou/` と `/kaiyou-sou/fukuoka/` には既に「すべてを海に還さなくても、かまいません」というセクションがあり、手元供養とメモリアルジュエリーの2枚が並んでいます。teraumiはその**3枚目**として入れます。ユーザーから見ると新サービスの登場ではなく、**いま読んでいた話の続き**です。

**2つ目は、診断で「すべて還したい」人にteraumiを見せないこと。** 質問は1問しか増やしません。しかもその1問は「一部は残したい」を選んだ人にしか出ません。仕様§4が指定する「teraumiが不要な方」の線引きを、文章ではなく**表示ロジックで**守ります。読んでもらう努力より、そもそも見せないほうが確実です。

**3つ目は、通常の海洋散骨を1文も否定しないこと。** 旧サイトの中心的な訴求は「散骨すると手を合わせる場所がなくなる」という論法でした。これは仕様§3で禁止されていますし、そもそも縁の既存の海洋散骨ページの価値を自分で削る主張です。`/teraumi/` の「違い」セクションは比較表にせず、**向いている人の並列表**にして、通常の海洋散骨の列に「海そのものが、手を合わせる場所になります」と明記します。

### teraumiが問い合わせのボトルネックにならないために何をしたか

270,000円は委託海洋葬（54,450円）の**約5倍**です。ここが最大のリスクだと考えています。

対策は4つ。**料金をFVに出さない**（迷いから入る）。**料金セクションの直後に予算別の代替案を置く**（「海洋散骨＋分骨5,500円」への逃げ道を必ず用意する）。**主CTAを申込ではなく相談にする**。そして**GA4で「通常の海洋散骨ページのCV率」を統合前後で比較できるようにし、10%以上下がったらteraumiの露出を段階的に弱める**という撤退ラインをあらかじめ決めておくことです。

teraumiは選択肢の1つであって、主力のCVを削ってまで押す対象ではありません。**下げられる設計**にしておくことが、いちばん確実なボトルネック対策だと考えました。

### teraumi.com のSEO・被リンク資産をどう引き継ぐのか

**301を1対1で、1ホップで通す**のが基本です。224URLすべてに転送先を決めました。記事57本は分類ごとに転送先を変え（A→新記事、B→統合先、C→本体のアンカー、D→本体トップ）、タグのうち検索意図が明確な7本も個別に振り分けています。一括転送で済ませないのは、**内容が近いURLへ送るほど評価が引き継がれる**からです。

そして**ドメインを手放さない**こと。これが最大の被リンク対策です。301が生きている限り評価は移り続けます。

被リンクについては正直にお伝えしますが、**バックアップからは分かりません**。分かったのは「teraumi が外部へ張っていたリンク」＝掲載された媒体です。実測にはGSCかAhrefsが要ります。そのうえで、依頼の優先順位は**PR TIMES → 提携寺院26件 → 日本海洋散骨協会 → 報道各社**としました。PR TIMESが自社配信で変更可能性が高く、転載先が多いためです。提携寺院への連絡は統合の周知としても必要なので、リンク変更依頼と同時に行うのが効率的です。

### GEO / MEO / LLMO までどう一貫させたのか

**同じ事実を、4つの場所に同じ言葉で置きます。**

`/teraumi/#temples` に書く「提携先12都府県・実名19件」「散骨海域15か所」「鹿児島本社・福岡営業所」という事実を、そのまま `llms.txt` の新設節に、`Service` 構造化データの `areaServed` に、GBPのサービス項目に反映します。NAPは「坂之上7丁目7-3」表記に統一します（旧サイトの「坂之上7-7-3」表記との揺れを解消）。

AI検索向けには、**4つの供養方法の違いを `llms.txt` に明示的に定義**します。「海洋散骨のみ／＋手元供養／＋寺院納骨（teraumi）／寺院納骨のみ」を、それぞれ料金と条件つきで書き分けます。AIが取り違えやすいのはここだからです。本文も「全国対応しています」のような主語のない文を避け、「有限会社 縁は、〜を提供しています」という主語述語のある文で書きます。**人が読んでも、AIが読んでも、同じ意味に取れる文章**にします。

MEOでは teraumi 専用のGBPを作りません（仕様§22）。作れば「別ブランド」というシグナルをGoogleに送ることになり、SEO・GEO・LLMOでやろうとしている統合と矛盾します。既存2拠点のGBPにサービス項目を1つ足すだけにします。
